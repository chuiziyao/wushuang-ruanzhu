# 字段规格与填法

按中国版权保护中心「R11 软件著作权登记申请」在线表单逐项对齐。字数为官网输入框实时计数，超出无法保存。**本表数值以截图实测为准，官网若改版，以系统提示为准。**

## 页签总览

```
① 选择办理身份 → ② 软件申请信息 → ③ 软件开发信息 → ④ 软件功能与特点 → ⑤ 确认信息 → ⑥ 填报完成
```

六步中只有 ②③④ 需要填内容，①是主体身份，⑤是逐字复核，⑥生成签章页。

---

## ② 软件申请信息

| 字段 | 类型 | 限制 | 填法 | 示例 |
|---|---|---|---|---|
| 权利取得方式 | 单选 | 必填 | 自研一律「原始取得」；受让、继承才选「继受取得」 | 原始取得 |
| 软件全称 | 文本 | 必填，建议 ≤ 25 字 | 「品牌 + 核心功能 + 软件/系统/平台」。**不带版本号**，不用简称，与页眉、手册三处逐字一致 | 示例事项记录软件 |
| 软件简称 | 文本 | 可空 | 无简称**留空**，不要填「无」「/」「-」；不得与全称相同 | 示例事项 |
| 版本号 | 文本 | 必填 | `V1.0` 或 `1.0` 二选一，全篇统一。页眉写什么这里就写什么 | V1.0 |
| 权利范围 | 单选 | 必填 | 自研且无共有、无职务作品争议时选「全部权利」 | 全部权利 |

**易错点**

- 全称里塞了 `V1.0`，版本号栏又填一次 —— 证书上会出现两个版本号。
- 简称填「无」—— 系统会当成简称就叫「无」，证书上印出来。
- 全称带「（鸿蒙版）」「Pro」这类渠道后缀 —— 与上架名不一致时要走变更，先想清楚。

## ③ 软件开发信息

| 字段 | 类型 | 限制 | 填法 | 示例 |
|---|---|---|---|---|
| 软件分类 | 下拉 | 必填 | 以系统下拉为准，绝大多数选「应用软件」；系统底层选「系统软件」，驱动/固件选「嵌入式软件」，中间层选「中间件」 | 应用软件 |
| 软件说明 | 单选 | 必填 | 新申请选「原创」；在原登记基础上改功能选「修改」，需填原登记号并附原证书 | 原创 |
| 开发方式 | 单选 | 必填 | 自己团队写＝「单独开发」；多人分工但有协议＝「合作开发」；外包＝「委托开发」；上级下达＝「下达任务开发」 | 单独开发 |
| 开发完成日期 | 日期 | 必填 | 软件全部固定在有形载体上的日期。**不得早于著作权人成立日期**，不得晚于今天 | 2026-09-30 |
| 发表状态 | 单选 | 必填 | 上架应用市场、网上发布、对外提供服务都算「已发表」；纯内部使用或未公开选「未发表」 | 已发表 |
| 首次发表日期 | 日期 | 已发表时必填 | ≥ 开发完成日期 | 2026-10-08 |
| 首次发表地点 | 文本 | 已发表时必填 | 写具体渠道名 | 华为应用市场 |
| 著作权人 | 复合 | 必填 | 国别「中国」→ 省市「江苏 / 南京」→ 类别「企业法人」（个人选「自然人」）→ 名称按营业执照**全称**→ 证件类型「统一社会信用代码证书」→ 号码 18 位逐字核对 | 示例科技有限公司 / 91320100MA1ABCDE2X |

**易错点**

- 用简称当著作权人名称 —— 工商全称差一个字就不予受理。
- 开发完成日期随手填成三年前，而公司两年前才成立 —— 补正。
- 已发表却把首次发表日期填得比开发完成日期早 —— 逻辑矛盾，补正。

## ④ 软件功能与特点（一）环境与语言

六栏全部 ≤ 50 字，超一个字都存不进去。写法是「名词清单」，不写句子。

| 字段 | 限制 | 写法 | 示例 |
|---|---|---|---|
| 开发的硬件环境 | ≤ 50 | 机型 + 关键规格，不写品牌型号全称 | PC：Intel i7 四核 2.8GHz / 16GB 内存 / 512GB 固态 |
| 运行的硬件环境 | ≤ 50 | 最低运行配置或目标设备 | 智能手机：4 核及以上 CPU / 4GB 及以上内存 |
| 开发该软件的操作系统 | ≤ 50 | 开发机系统 | Windows 11 64 位 / macOS 14 |
| 软件开发环境/开发工具 | ≤ 50 | IDE + 构建 + 版本管理 | DevEco Studio 5.0、Android Studio、Git、Gradle |
| 该软件的运行平台/操作系统 | ≤ 50 | 目标平台及最低版本 | HarmonyOS 4.0 及以上 / Android 8.0 及以上 |
| 软件运行支撑环境/支持软件 | ≤ 50 | 依赖的运行时、数据库、中间件；无依赖就写「无需额外支撑软件」 | 无需额外支撑软件，系统内置运行环境即可 |
| 编程语言 | 多选标签 | 勾选官方标签；标签里没有的写进「其他编程语言」 | ArkTS、Kotlin、SQL、其他 |
| 其他编程语言 | ≤ 120 | 一句话说明每种语言的用途，别只列名字 | ArkTS 用于鸿蒙端界面与状态管理，Kotlin 用于安卓端，SQL 用于本地数据库 |
| 源程序量 | 数字＋「行」 | 取项目扫描的**有效行数**（去空行），与代码 Word 口径一致 | 18642 |

**易错点**

- 运行平台写「全平台」—— 审查无法对应，写具体系统与最低版本。
- 编程语言漏勾（如只勾 Python 但代码里有大量 JS）—— 与代码不符。
- 源程序量填一个整数估的数，和提交的代码 Word 行数差几倍 —— 自己给自己挖坑。

## ④ 软件功能与特点（二）功能描述

| 字段 | 限制 | 写法 |
|---|---|---|
| 开发目的 | ≤ 50 | 「解决谁的什么问题」一句话，不写产品愿景 |
| 面向领域/行业 | ≤ 50 | 行业 + 应用场景，可带一句技术归属 |
| 软件的主要功能 | **500–1300 字** | 五段式，见 `02_主要功能写作模板.md`。这是审查员唯一细读的段落，必须与代码目录、类名对得上 |
| 软件的技术特点 | 多选标签 | 勾 1–3 个，宁少勿多；与功能描述不矛盾的才勾 |
| 技术特点补充 | ≤ 100 | 只写一个真正的技术点，写清「怎么做的 + 换来什么」 |

技术特点标签全集（官网现列为准）：APP、游戏软件、教育软件、金融软件、医疗软件、地理信息软件、云计算软件、信息安全软件、大数据软件、人工智能软件、VR软件、5G软件、小程序、物联网软件、智慧城市软件。

**易错点**

- 主要功能写 400 字 —— 系统直接拦，提交不了。
- 主要功能写 1300 字全是形容词 —— 内容空，审查提补正要求说明与代码的对应关系。
- 技术特点补充写「界面美观、操作便捷」—— 不是技术特点。

## ④ 软件功能与特点（三）鉴别材料

| 字段 | 限制 | 填法 |
|---|---|---|
| 程序鉴别材料 | 单选 | 「一般交存」＝前 30 页 + 后 30 页（总量不足 60 页交全部）；涉及商业秘密需隐藏部分代码才选「例外交存」 |
| 文档鉴别材料 | 单选 | 同上。文档类型在用户手册 / 操作说明书 / 设计文档中任选一种，**推荐操作说明书** |
| 其他相关证明文件 | 可选 | 委托开发合同、合作开发协议、原登记证书等；无则不传 |

上传只接受 PDF。单个文件上传前压到 20MB 以内。

## 50 字字段的写法公式

`主体 + 规格/版本 + 关键限定`

- 硬件：`设备类型：CPU / 内存 / 存储`（三项足够，删掉品牌）
- 系统：`系统名 + 版本号`，两个系统用「/」分隔，不用「等」「以上」以外的修饰
- 工具：`IDE、构建工具、版本管理`，只留三个最关键的
- 目的：`为谁 + 解决什么 + 达到什么`，一句话，不带形容词
- 领域：`行业 + 场景`

写超了就按这个顺序删：品牌型号 → 数量词 → 「等」列举 → 形容词。剩下的才是审查要看的信息。
