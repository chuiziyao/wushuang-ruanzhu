# 「软件的主要功能」写作模板

这一栏是审查员唯一细读的段落：**500–1300 字，少于 500 字系统直接拦**。判据只有一条——文字描述能不能在提交的源代码里找到对应的目录、类、函数。写得漂亮但代码里找不到，等于给补正递刀。

## 五段骨架

| 段 | 内容 | 字数 | 硬要求 |
|---|---|---|---|
| 1 定位 | 面向谁、在什么场景、用什么方式完成什么事 | 60–100 | 出现软件全称的核心功能词 |
| 2 模块 | 4–6 个模块，逐个说明「叫什么 + 做什么 + 怎么触发 + 产出什么」 | 300–600 | 模块名必须与代码目录/类名/文件名对得上 |
| 3 数据 | 数据从哪进、存哪里、怎么算、怎么出 | 100–200 | 提到具体存储形态（本地库 / 服务端库 / 文件） |
| 4 边界 | 权限、离线、脱敏、异常处理、容量约束 | 60–120 | 至少写一条真实的限制条件 |
| 5 形态 | 交付形态：端类型、部署方式、输出去向 | 40–80 | 与「运行平台」栏不矛盾 |

模块段的固定句式（照用，比自由发挥稳）：

```
软件包含五个核心模块：一是××模块，用于……，用户……后……，输出……；
二是××模块，依据……计算……，结果以……呈现；
三是××模块，按……维度汇总……；
四是××模块，采用……存储……，支持……；
五是××模块，提供……、……与……。
```

## 三条写作纪律

1. **一个模块一句话说完**，句子里必须有动词和产出物，不写「提升用户体验」这类无验证对象的判断。
2. **数字和口径写具体**：按日/周/月、前 30 天、单文件 ≤ 20MB、并发 50。审查不核对数字真伪，但空泛描述会被要求补充说明。
3. **不写营销词**：赋能、闭环、极致、一站式、颠覆。换成「支持」「提供」「按照……计算」。

## 范例 A：移动端工具类（约 610 字）

> 适用：App、鸿蒙/安卓客户端、小程序。可直接替换模块名复用。

本软件面向个人时间管理场景，提供以事件为最小单位的轻量记录能力。用户在主界面点击预置事件或自定义事件即可完成一次记录，系统自动写入本地数据库并刷新当日统计。软件包含五个核心模块：一是事件记录模块，支持预置事件与自定义事件的增删改，记录时可附带持续时间、备注与附件，附件支持拍照与相册选取，点击附件可全屏查看；二是时间预测模块，依据历史记录的出现频次与间隔，用加权移动平均推算下一次可能发生的时间，并在界面上以提示条展示，用户可通过开关关闭该预测；三是统计复盘模块，按日、周、月三个维度汇总事件次数与总耗时，输出时间分配占比与趋势折线；四是本地数据模块，采用本地关系型数据库存储事件、记录与附件索引，支持按时间范围筛选与批量导出；五是设置模块，提供中英文界面切换、提醒开关、数据导出与清空、版本信息展示。事件记录模块在录入时即校验时间合法性与备注长度，避免非法数据入库；统计复盘模块的数值均由本地记录实时计算，不依赖服务端接口。所有数据默认仅保存在设备本地，不上传服务器，卸载后数据随之清除，用户亦可在设置中手动导出为结构化文件后再清空。界面采用卡片式布局，首页仅保留两个高频预置事件以降低选择成本，其余事件收纳在事件库中；附件与记录采用索引关联，删除记录时可选择保留或一并清理附件，避免存储空间被无主文件占用。软件以安装包形式交付，支持离线启动，首次进入引导完成基础事件配置。

## 范例 B：Web 平台类（约 640 字）

> 适用：管理系统、SaaS、内部平台、带服务端的网页应用。

本系统面向机构内部的资产信息整理场景，把分散在公告、报表与人工台账中的数据归并为统一口径的结构化记录，供研究与对外披露使用。系统包含五个核心模块：一是数据采集模块，按配置的任务清单抓取指定来源的公告与报表，解析为字段级记录并写入数据库，失败任务进入重试队列并记录原因；二是字段映射模块，依据预置映射表把不同来源的同义字段对齐到统一字段名，口径冲突时保留来源标记，供人工复核；三是口径计算模块，按面积、租金、出租率三类指标的既定公式逐项推导，每一步中间值单独入库，支持回溯计算链；四是审核发布模块，提供待审列表、逐条通过或退回、批量发布，发布后生成带版本号的只读快照；五是权限与日志模块，按角色划分查看、编辑、发布三类权限，所有写操作记录操作人、时间与变更前后值。系统采用前后端分离结构，前端负责表格与图表呈现，后端提供接口并按任务调度执行采集与计算，数据存放于服务端关系型数据库，文件与导出物存放于对象存储。单条记录的全部字段均带来源页码与原文位置，便于人工核对；采集任务支持断点续跑，重复抓取不产生重复记录。系统以浏览器访问方式交付，支持局域网内部署，导出物为结构化表格与 PDF 报告。

## 范例 C：算法/模型类（约 590 字）

> 适用：识别、预测、评估、检索类软件。重点写清输入、处理链、输出与评测。

本软件面向公开市场披露文本的自动整理与问答场景，把非结构化的文件解析为结构化记录，并在其基础上提供限定范围的检索与问答能力。软件包含四个核心模块：一是文档解析模块，按页读取文件中的文字与表格坐标，聚合成行级记录并保留页码与位置信息，表格单独走结构化通道，不参与文本切分；二是结构化入库模块，按主体、期间、指标三元组写入数据库，同一指标的不同口径分别存储，主键包含口径字段以避免覆盖；三是检索模块，对文本记录建立倒排索引，查询时先按关键词召回再按相关度重排，返回结果附带原文位置，供人工定位；四是问答模块，将结构化查询与文本检索两条通道分开处理，事实型问题走字段查询，语义型问题走检索加摘要，答案中标注依据的记录编号与文件页码。解析模块对缺页、乱码与坐标异常设有校验规则，校验不通过的记录不进入结构化库，宁缺勿错；检索模块对超出索引范围的问题返回明确的范围说明，不拼接无依据内容。软件以命令行工具与服务接口两种方式交付，可部署于单机或内网服务器，输出物为结构化数据文件、检索结果清单与问答记录。

## 字数不达标的补法（按优先级）

1. 给每个模块补「触发方式 + 产出物」，一句话能加 25–40 字。
2. 补第 3 段的数据流向：数据从哪来、存哪、怎么算、怎么出。
3. 补第 4 段的限制条件：权限、离线、容量、异常处理。
4. 补模块之间的衔接：A 模块的结果如何被 B 模块使用。

## 字数超标的删法

1. 删形容词与副词整句（「极大地提高了」「有效地解决了」）。
2. 删与代码无关的行业背景铺垫。
3. 把并列的同义描述合并（「方便」「便捷」「简单」三选一）。
4. 模块从 6 个减到 5 个，保留代码里最核心的。
