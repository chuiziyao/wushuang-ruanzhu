# 版式规范：封面、页眉、页脚

这份规范只管三件事：**封面放什么、页眉写什么、页脚不许写什么**。三件事定死，材料就不会因为「看着不像正式文件」被挑。

一句话原则：**软著材料的版面上只允许出现三类信息——软件全称、版本号、页码。** 其余一律不要：公司名（封面除外）、日期、Logo、网址、二维码、"内部资料""AI 生成"之类标记。

---

## 一、页眉：左全称、右页码

| 项 | 规格 | 说明 |
|---|---|---|
| 位置 | 页眉区一行，左侧顶左边界 | 页眉距上边界 1.2cm，不侵占正文 |
| 左内容 | `软件全称 V1.0` | 与申请表「软件全称」「版本号」逐字一致，中间一个半角空格 |
| 右内容 | `第 X 页 共 N 页` | X 用 PAGE 域（自动），N 用写死数字或 SECTIONPAGES / NUMPAGES 域 |
| 字体字号 | 宋体 9pt，不加粗，纯黑 | 比正文小一号，不抢视线 |
| 分栏方式 | 一个右对齐制表位，位置＝右边界 | 不用空格硬顶，不用两栏表格 |
| 分隔线 | 页眉下一道 0.75 磅黑色实线 | 段落下框线，不是插图形，不要双线、不要彩色 |
| 页脚 | **留空** | 见第二节 |

### 页码为什么必须贴右边界

「第 X 页 共 N 页」是靠**右对齐制表位**顶到右边界的，不是靠敲空格。这里有个隐蔽的坑：

Word 的「页眉」样式自带两个制表位——8.25cm 居中、16.5cm 右对齐。如果只在段落里加一个 17.4cm 的右制表位，页眉那个 Tab 会**先命中样式里的 8.25cm 居中位**，页码落在页面中间偏右，看起来像居中，不像右上角。

正确做法两条同时做：

1. 清掉「页眉」样式自带的制表位（`docx_common._clear_style_tabs`）；
2. 段落里显式写 `<w:tab w:val="clear" w:pos="4680"/>`、`<w:tab w:val="clear" w:pos="9360"/>`，再加唯一的右制表位。

鉴别方法：打开 Word，把光标放在页码前按 Tab，看它跳到横向标尺的哪个位置；或者直接跑 `check_docx.py`，它会把「继承了页眉样式的居中制表位且未清除」报出来。

### 页眉的三种总页数取值

| 取值 | 写法 | 用在哪 | 好处 |
|---|---|---|---|
| 写死数字 | 生成时算出的真实页数 | 程序鉴别材料、前 30 页 + 后 30 页 | 页数由生成器决定，不依赖 Word 事后排版，最稳 |
| `NUMPAGES` 域 | 全文总页数 | 文档鉴别材料不要封面时 | 改内容自动更新 |
| `SECTIONPAGES` 域 | 本节总页数 | 文档鉴别材料有封面时 | 「共 N 页」不含封面，页码与文字不打架 |

`docx2pdf.py` 在导出前会调 `Fields.Update()` 刷新域，所以导出的 PDF 里页码是真值，不是缓存占位。

## 二、页脚：留空，一格都不写

页脚是软著材料里最容易画蛇添足的地方。以下内容**一律禁止**出现在页脚：

- 公司名、部门名、"编制：×××"
- 日期、"2026 年 10 月"
- "内部资料""仅供审查""请勿外传""AI 生成""请谨慎甄别"
- 网址、邮箱、二维码、公众号
- 第二行页码（页码已在页眉右上角，页脚再写一遍会出现两套编号）

理由很实在：审查员比对的是**申请表、源代码、说明书三者的一致性**。页脚多一行公司名，等于多一个可能与营业执照措辞不一致的比对点；多一行日期，等于多一个可能与开发完成日期冲突的字段。少写一行，少一个被问的可能。

## 三、封面：只有文档鉴别材料有

程序鉴别材料（源代码）**不做封面**，第 1 页正文就是代码，页眉从第 1 页出现。多一页封面，前 30 页的代码量就少 50 行，得不偿失。

文档鉴别材料（用户手册 / 操作说明书）封面独占第 1 页，自上而下四段：

```
        著作权人全称（12pt，宋体，字距 1pt）
        软件全称（26pt，黑体加粗，字距 2pt）
        版 本 号　V1.0（12pt，宋体）
        用 户 手 册（22pt，黑体加粗，字距 6pt）
```

| 项 | 规定 |
|---|---|
| 页面 | 独占一页，内容垂直居中偏上 |
| 页眉页码 | **不显示**（封面独立成节，页眉页脚都为空） |
| 页码起算 | 正文第 1 页重新起算，页眉「共 N 页」不含封面 |
| 不放日期 | 日期与申请表开发完成日、公司成立日容易对不上，宁可没有 |
| 不放 Logo / 网址 / 二维码 | 与材料无关，且引入额外比对点 |

技术实现：封面与正文分成两节（`WD_SECTION.NEW_PAGE`），第 1 节页眉页脚显式清空，第 2 节设 `pgNumType start=1` 并用 `SECTIONPAGES`。这样封面干净、正文页码从 1 开始、总页数不含封面，三者自洽。

## 四、两份材料的版式对照

| 项 | 程序鉴别材料（源代码） | 文档鉴别材料（说明书） |
|---|---|---|
| 封面 | 无 | 有，独占第 1 页 |
| 纸张 | A4 纵向 21×29.7cm | 同 |
| 页边距 | 上 2.0 / 下 1.8 / 左右 1.8cm | 上 2.2 / 下 1.8 / 左右 2.2cm |
| 可用宽度 | 17.4cm | 16.6cm |
| 页眉 | 全称 + 版本号 / 第 X 页 共 N 页 / 9pt / 下框线 | 同 |
| 页脚 | 空 | 空 |
| 正文字体 | Consolas 9pt（中文回退宋体） | 宋体 10.5pt，标题黑体 |
| 行距 | 固定 14 磅，每页 50 行 | 1.35 倍行距，每页 ≥30 行 |
| 空行 | 全文禁止 | 段落间距代替空行 |

## 五、六个常见错法（都见过实物）

| 错法 | 后果 | 怎么改 |
|---|---|---|
| 页码写成「第 1 页 / 共 30 页」并居中或靠右浮动 | 斜杠格式非规范写法；静态文字改页数不更新 | 改为「第 X 页 共 N 页」，X 用 PAGE 域，靠右制表位 |
| 页脚写「软件名 + 公司全称」，页码放页脚 | 页眉空着、页脚堆字，版式重心颠倒，多两处比对点 | 软件名上行到页眉左侧，页码上行到页眉右侧，页脚清空 |
| 「共 N 页」写的是完整稿页数（如 133 页），交的却是 30 页 | 页码与实物对不上，属硬伤 | 交 60 页就写 60，或用域自动算 |
| 封面也显示页眉与「第 1 页」 | 封面被当成正文第 1 页，总页数口径混乱 | 封面独立成节，页眉页脚清空，正文重新起算 |
| 页眉页码落在页面中间 | 要求「右上角」，视觉上像居中 | 清掉样式自带制表位，只留右边界一个 |
| 正文用固定行距（`w:lineRule="exact"`）且段落含行内图片 | 行框高度被钉死，图片按行高裁剪，Word 与 PDF 里截图都只剩一条十几像素的细条 | 含图段落改倍数行距（`line_spacing = 1.0`），正文整体用倍数行距 |

### 为什么固定行距会裁图

`line_spacing = Pt(x)` 在 XML 里写成 `<w:spacing w:line="280" w:lineRule="exact"/>`，Word 把这一行的高度固定为 x 磅。行内图（`wp:inline`）的显示尺寸由 `wp:extent` 决定，但绘制时受行框裁剪，PDF 内容流里就出现一个只有行高那么高的裁剪矩形：

```
-1638.4 185.5 3809.7 19.25 re W* n     ← 裁剪框高度 19.25pt
q 442.2 0 0 -267.36 76.44 198.48 cm /IM27 Do Q   ← 图片本身 442×267pt 是对的
```

图片矩阵没错、PNG 没错、`r:embed` 没错，错在裁剪框。改倍数行距后，同一个图绘制前的裁剪框是整个页面高度（841.9pt），图片完整显示为 15.60×9.43cm。

行距设置分三层生效，改的时候三层都要看：段落直接设置 → 段落样式（含 `basedOn` 链）→ 文档默认。只改段落级、样式级仍是 `exact`，一样会被裁。

例外：源代码材料的固定 14 磅行距必须保留，那是「每页 50 行」的前提。源代码里没有图，两者不冲突。

## 六、自检

生成完先跑版式体检，不看内容只看版式：

```bash
python scripts/check_docx.py 源代码_完整.docx --audit-only
python scripts/check_docx.py 操作说明书.docx --kind manual --audit-only
```

体检项：纸张、四条页边距、页眉距边界、页眉字号、右制表位位置、是否含居中/左对齐制表位、下框线、PAGE 域、页脚是否为空、封面是否带页眉、是否出现「AI 生成」等字样、**含行内图片的段落是否使用固定行距**。

最后一项是硬伤探测：只要段落含 `wp:inline` 图且生效行距为 `exact`，就报「截图会被裁成一条」，并指明行距值来自段落还是哪个样式。转换前的 docx 就能查出来，不用等导出 PDF 才发现。

只看版式不动内容时加 `--audit-only`，行数与页数判断会跳过，方便体检别人做的材料。

体检通过后转 PDF，再打开 PDF 用肉眼确认三处：总页数、第 1 页页码、最后一页页码。三处对上，版式就没有问题了。
