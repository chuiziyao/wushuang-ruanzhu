# 无双软著申请

> 版本 V1.0　｜　作者：锤无双　｜　交流 QQ 群：170621740

中国版权保护中心「R11 软件著作权登记」的材料流水线。官网六页表单、两份程序鉴别材料、一本操作说明书，压成一条命令链：文字从开发记录推出来，页数由生成器算出来，不留占位符。

```
自检环境 → 登记三项 → 扫项目 → 填字段校验 → 源代码 Word ×2 → 说明书 Word → 出 PDF → 自查单
```

## 手工做的代价

| 环节 | 手工 | 本技能 |
|---|---|---|
| 表单六页签 | 逐项猜填法，超字数保存不了，来回改 | 字段规格内置，逐项标注「实际 X 字 / 上限 Y」，超一个字符直接报错 |
| 主要功能 500–1300 字 | 写完不知道够不够 | 校验器卡死区间，低于 500 直接判定系统会拒收 |
| 源代码 Word | 粘进 Word 调行距、补页码，一改就跑版 | 固定行距预分页，页数由生成器算，Word 重排后页数不变 |
| 每页 50 行 | 靠眼睛数，翻车率极高 | 生成时按行切页，回验脚本逐页数行 |
| 前 30 页 + 后 30 页 | 手工复制拼接，页码容易错 | 一条命令出第二份，页码模式二选一 |
| 转 PDF | 打印到 PDF 一缩放，50 行变 45 行 | 调本机 Word 的 COM 导出，不缩放不压行距 |

## 装

技能目录直接克隆进去即可，不需要装任何 Python 包：

```bash
git clone https://github.com/chuiziyao/wushuang-ruanzhu.git \
  ~/.workbuddy/skills/无双软著申请
```

Windows 下路径为 `C:\Users\<用户名>\.workbuddy\skills\无双软著申请`。

也可以把本仓库压缩包解到该目录，效果相同。目录名必须与 `SKILL.md` 中的 `name` 一致，否则技能不加载。

国内直连 github.com 偶有连接重置，克隆失败时换镜像域名、挂代理，或直接在网页上下载仓库压缩包再解压。

## 首次使用

### 1. 自检

```bash
python scripts/bootstrap.py
```

它报告四件事：Word 生成能力、PDF 出稿方式、PDF 截页合并能力、字体是否齐。原则是**能不下载就不下载**：

| 能力 | 首选（本机自带，零下载） | 兜底 |
|---|---|---|
| 生成 Word | python-docx，多数环境已有 | 缺失时 `--install` 走清华镜像装，几百 KB |
| 出 PDF | 本机 Word 的 COM 导出（43 页约 4 秒） | 依次降级 WPS → LibreOffice → 只出 docx |
| PDF 截页合并 | pypdf，纯 Python 几十 KB | 缺失时 `--install`，或在 Word 里导出指定页范围 |

刻意不依赖 PyMuPDF 这类大二进制包：国内拉取慢、失败率高，而交付需要的能力本机 Word 加 pypdf 已经够。

### 2. 登记三项

```bash
python scripts/bootstrap.py --owner "申请人全称" --name "软件全称" --version V1.0 \
    --root <项目目录> --outdir <材料输出目录>
```

生成 `00_基本信息.json`。之后所有脚本在当前目录向上查找该文件，不必重复传参。顺手能问到统一社会信用代码与成立日期就一起写进 `--credit-code` / `--founded`，日期逻辑校验要用。

### 3. 六步流水线

```bash
SKILL=~/.workbuddy/skills/无双软著申请

python $SKILL/scripts/scan_project.py --root <项目> --out 02_项目扫描.json
python $SKILL/scripts/check_form.py --init     # 模板已预填申请人、软件名、版本号
python $SKILL/scripts/check_form.py            # 校验并出 01_填报清单.md
python $SKILL/scripts/gen_source_docx.py       # 源代码 Word，>60 页自动多出前30后30
python $SKILL/scripts/check_docx.py 源代码_完整.docx --expect-lines 50
python $SKILL/scripts/gen_manual_docx.py --md 操作说明书.md --chapter-pagebreak
python $SKILL/scripts/docx2pdf.py --input 源代码_完整.docx --output 源代码_完整.pdf
python $SKILL/scripts/make_checklist.py        # 05_自查单.md
```

## 字段限制（官网输入框实测）

按 R11 在线表单逐项对齐。超出下限或上限，系统直接拒绝保存。

| 字段 | 限制 | 说明 |
|---|---|---|
| 开发的硬件环境 / 运行的硬件环境 | ≤ 50 字 | 写具体配置，不写「主流配置」 |
| 开发操作系统 / 运行平台 | ≤ 50 字 | 逐一列出，多个系统用顿号 |
| 开发环境工具 | ≤ 50 字 | IDE、构建工具、版本管理 |
| 支撑软件 | ≤ 50 字 | 运行时依赖，如数据库、中间件 |
| 其他编程语言 | ≤ 120 字 | 标签外语言集中写在这里 |
| 软件的主要功能 | **500–1300 字** | 少于 500 字系统拒收 |
| 技术特点补充 | ≤ 100 字 | 超字无法保存 |
| 软件简称 | 可空 | 无简称**留空**，不要填「无」「/」「-」 |

## 源代码 Word 的三条死约束

三条同时锁死，才不会跑版：

1. **固定行距 14 磅**。50 行 = 700 磅，A4 可用高度 728.5 磅，余 28.5 磅。行距一浮动，页数就变。
2. **每页首段强制分页**（`pageBreakBefore`），不靠自然分页。
3. **按显示宽度预折行**，中文字符记 2 格，单行上限 96 单位约 475 磅，小于可用宽度 482 磅。中文注释撑不破右边界。

这份材料的页数不是排版出来的，是算出来的。第二份「前 30 页 + 后 30 页」用 `--number-mode` 切换：

- `continue`（默认）：页码 1–60 连续，页眉「共 60 页」，自成一体
- `original`：后 30 页沿用完整稿真实页码，如 549–578

两种都合规，关键是同一份材料内不要混用。

## 边界

- **不代办账号**：注册、企业实名认证、打印签章页盖鲜章、上传，必须本人在官网完成。签章页回传有时限，逾期视为未提交，`references/04` 有完整流程。
- **不出 AI 界面图**：说明书里的界面截图必须是真实截图，缺图时脚本留占位文字提醒，不生成示意图充数。
- **不猜代码**：「主要功能」要与真实目录、类名、函数名对得上，功能描述全是形容词会被质疑。
- **不伪造行数**：源程序量按代码 Word 的有效行数取值，与材料同口径。

## 常见问题

**没有装 Word 怎么办？**
只出 docx，在任意装有 Office 的机器上另存 PDF。其余环节不受影响。

**每页 50 行够不够？**
官方原文是「每页不少于 50 行」，50 即达标。若要求严格多于 50，加 `--lines-per-page 51`，14 磅行距仍装得下；52 行需同时降 `--line-pt 13.5`。

**缺 Consolas 字体？**
加 `--font-ascii "Courier New"`，等宽宽度接近，不影响行数与折行计算。

**总页数超过 60 页一定要交两份？**
是。完整稿留档，另交「前 30 页 + 后 30 页」的摘取版，两处页码模式别混用。
